# Agent Note: 规划模型设置由 Host 持有

Status: implemented

[English](2026-09-20-plan-model-settings-host-ownership.md) | 中文

## Problem

规划/执行模型卡片是用于配置未来会话的浏览器界面，但它的 settings 命名空间由 Agent 平面运行时注册。该运行时只在使用 `plan-execute` 预设的会话挂载期间存在。首个此类会话启动前以及最后一个会话关闭后，Host 都不会描述 `plan-model-switch` 命名空间，因此设置标签页会隐藏卡片。要求用户先启动目标模式再配置它，颠倒了这项设置本来要支持的创建顺序。

由每个会话注册命名空间，还会让共享用户偏好依赖会话生命周期。多个并发的计划/执行会话可能尝试注册同一个唯一命名空间，而关闭其所有者会让其他所有会话一并失去配置界面。

## Decision

`@deepseek-ai/dsh-plan-model-switch/settings` 是 `plan-model-switch` settings 命名空间唯一的 Host 平面所有者。base bundle 会把它挂载在 settings 提供方旁边，因此每个基于 base 的 profile 都会在整个 Host 生命周期中描述该命名空间。Web 卡片继续遵循普通的已服务命名空间目录，无需特殊的可见性例外即可渲染。

`@deepseek-ai/dsh-plan-model-switch` 根导出仍是由 `plan-execute` 预设挂载的 Agent 平面运行时。它不注册命名空间。在每个计划阶段边界，它会读取 Host 所有者解析后的分节：伴生插件行配置提供组合默认值，已保存的用户选择优先于这些默认值。没有 Host 伴生插件或 settings 提供方时，运行时使用自身条目。

settings 所有者与运行时是两个独立的包导出，因为它们的生命周期和依赖不同：所有者只需要 `ctx.settings`；运行时需要计划模式与会话投影。运行时不进入 Host，可以避免在全局安装阶段监听器；所有者不进入 Agent realm，可以避免会话销毁时移除共享配置。

## Alternatives considered

**在浏览器中始终派发卡片键。** 卡片的 settings scope 仍不可用，因此共享卡片外壳仍会什么都不渲染；强制显示只会得到无法保存值的禁用控件。拒绝此方案，因为可见性必须对应真实可写的 settings 所有者。

**把完整运行时挂载到 Host。** 运行时依赖 Agent 平面的计划模式状态，要么会永远等待这些服务，要么会在错误的 realm 中安装阶段监听器。拒绝此方案，因为配置所有权不等于运行时所有权。

**继续让首个计划/执行会话持有命名空间。** 这样配置在用户需要它时仍不可用，而且命名空间生命周期会依赖任意一个会话。拒绝此方案。

## Consequences

- 只要连接到基于 base 的 Host，规划/执行模型卡片就会存在，包括未打开任何会话以及当前选择 `standard` 预设时。
- 保存卡片不会为未挂载运行时的预设启用阶段路由；卡片文案会说明只有组合了阶段路由的预设才受影响。
- 不使用 `dsh-base` 的自定义部署若同时需要持久卡片和运行时行为，需要挂载两个导出，并把共享默认值放在 Host 伴生插件行上。
- 一个 Host 注册服务所有计划/执行会话，避免重复命名空间注册以及对会话顺序的依赖。

## Verification

plan-model-switch 集成测试固定 Host 生命周期注册、默认折叠值、运行时条目回退以及解析后 Host 设置的优先级。base bundle 测试固定 Host 伴生插件行。现有客户端设置测试继续固定只有被服务的命名空间才会派发，因此卡片可见性来自真实 Host 注册，而不是浏览器专用例外。
