# Agent Note: 单个待处理交互监视器负责浏览器通知

Status: implemented

[English](2026-11-12-pending-interaction-browser-notifications.md) | 中文

## 问题

审批、提问和计划确认只出现在会话视图内，页面在后台时就看不见唯一必须回答的事情。[审批](../../../../docs/subsystems/approval.zh.md)和[用户提问](../../../../docs/subsystems/user-questions.zh.md)已经共享 `uiSession` 的待处理交互投影，但会话视图之外没有任何东西能对它作出反应。

## 决策

新增一个客户端插件 `ui-attention`，观察 `ctx.uiSession.sessionStatus`，为每个待处理请求推送一条浏览器通知。每个请求在页面生命周期内最多提醒一次，且仅在 `document.visibilityState` 为隐藏、Host 偏好已启用、浏览器已授予权限时提醒。点击通知会回到窗口并打开发起该请求的会话。

启用偏好是一个 Host 设置命名空间（`ui-attention`，字段 `enabled`，默认 `false`），由插件自己的 **设置 → 通用** 行渲染。通知权限仍属于每个浏览器，并通过开关的用户手势申请，因为 Host 上的值无法授予它。

## 备选方案

**由各领域插件各自推送通知。** 否决：两个领域都要各自承担权限申请、隐藏页面判断和文案，而审批插件无法在另一个插件的字典里本地化文本。按领域给出通用标题，可以只保留一个监视器和一处文案归属。

**把开关存在浏览器里。** 否决依据是[共享 Host 偏好](../bug-fix/2026-09-15-authenticated-browser-host-preferences.zh.md)：偏好写入所有已认证浏览器共享的 Host 文档，该行改为说明尚未授予权限的浏览器。

**无论页面是否可见都通知。** 否决：页面内卡片已经覆盖可见窗口，多出来的提醒会与它竞争。

## 影响

通知文案给出领域和会话标题，而不是请求自身的措辞。请求在页面可见时出现，只有在它仍然等待、页面随后变为隐藏时才会提醒。请求的 key 改变视为新请求，会再次提醒。

## 测试

聚焦用例固定了监视器的单次提醒、可见性边缘、偏好与权限门槛、已应答请求的清理以及释放行为；行用例覆盖每种权限提示与只读禁用；组合用例接上真实设置表单，断言通知、被打开的会话以及释放时的行移除；Host 用例固定 schema 默认值、校验和被排除的生成页面。
